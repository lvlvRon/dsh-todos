# 交互规格与实现规划

> 配套 `PLAN.md`（架构与历法策略）、`design/ui-tree.md`（视觉结构）。
> UI 已定稿；本文覆盖**行为**与**落地步骤**。

## 一、交互规格

### 1.1 待办行

| 操作 | 行为 |
|---|---|
| 点圆环 | 完成 / 取消完成。**乐观更新**：先改 UI，Host 失败则回滚 + toast |
| 点标题 | 打开详情浮层（对话区保持常驻，不抢占） |
| hover | 行尾浮出「编辑 · 删除」 |
| 键盘 | ↑↓ 移动焦点、`Space` 勾选、`Enter` 编辑、`Delete` 删除、`Esc` 退出 |
| 拖拽排序 / 拖动改期 | **v1 不做**（YAGNI，收益低、和日历视图重复） |

### 1.2 新建

三个入口，最终都落到同一个「快速添加」输入行：

1. 顶部 `＋` 或快捷键 `N`
2. 日历点空白格（预填该日期）
3. AI 草案卡「全部创建」

行为：输入行插到列表顶部，`Enter` 创建并保持输入行（连续录入），`Esc` 取消，失焦保留草稿。

### 1.3 编辑

浮层表单：标题 / 日期 / 时间 / 标签 / 重要 / 紧急 / 备注。
保存 → 写库 → 关浮层；有未保存改动时关闭需二次确认。

### 1.4 删除

立即删除 + **5 秒撤销 toast**，不做二次确认弹窗。
理由：删除可回滚时，确认框是多余的摩擦。

### 1.5 筛选

`时间范围（今天/本周/本月/全部/已完成） × 标签 × 视图（列表/日历）`，三者互不阻塞。

默认：今天 + 全部标签 + 列表视图。

**记忆策略建议**：记住「标签」和「视图」，**不记住时间范围** —— 每次打开先看今天才是待办应用的正常预期。

### 1.6 草案卡（核心）

- 每个字段就地可编辑：日期 → 弹日历；时间 → 下拉；标签 → 下拉；优先级 → 「重要」「紧急」两个开关
- 缺失字段是**橙色虚线**，点开即补
- 「全部创建」在有缺失时禁用，并说明还缺什么（「还有 1 项缺日期」）
- 创建成功后卡片转只读态「已创建 2 条」，带「撤销」
- 单条可「忽略」，从草案中移除

### 1.7 对话

| 事件 | 行为 |
|---|---|
| 粘贴图片 | 进附件条；`×` 或 `Esc` 移除 |
| `Enter` | 发送；`Shift+Enter` 换行 |
| 发送后 | 输入禁用、typing 指示、附件转缩略图 |
| 流式 | 文字先流；草案卡在流结束后整体出现（避免半截 JSON） |
| 失败 | 保留输入与附件，显示原因 + 重试 |
| 清空 | `⋯` 菜单里，需确认 |

### 1.8 全局状态

空态（无待办 + 引导粘贴）· 骨架（加载）· 错误（AI 不可用 → **降级为手动建**，面板本身仍可用）· 离线同上。

## 二、实现规划

### 2.1 先做三个技术验证（约 1–2 小时）

在写业务代码之前必须确认，否则方案可能是空中楼阁：

| # | 问题 | 结论 / 备选 | 状态 |
|---|---|---|---|
| S1 | client↔host 通道用哪条 | **首选 `host.call(method, args)`**：DSH 内置的「Package-private JSON RPC from Client to this Package's Host half」，正是为双半插件设计的；无 HTTP、无鉴权负担。<br>备选 `ctx.webServer.register` 自挂路由（能用但不原生）。<br>**不能用** `@Remote`：client 侧只暴露 8 个 service，无通用入口，装配清单全是官方包。 | **未决点**：`host` builtin 文档写的是「dynamic Client half」（`cordis_define` 运行时插件）；安装式 bundle 的 `factory(require)` 能否拿到 `host`，需 10 分钟探针验证 |
| S2 | 浏览器 → Host 的图片通道与体积上限？ | 走 S1 确定的那条通道传 base64；浏览器侧先 canvas 压缩到 ≤1600px / ≤2 MB | 待 S1 后测 |
| S3 | client 单文件内联 4 KB 历法表 + 面板首屏渲染 | 内联 JS 字面量（已验证必须内联） | 待测 |

> **2026-11-22 验证完毕 —— 上面的推测表作废，以下为实测结论：**
>
> | 项 | 结论 |
> |---|---|
> | 原生 RPC `host.call` | ❌ 静态 bundle 的 client 半 `typeof host === 'undefined'`（那是 dynamic Client half 才有的内置符号） |
> | `@Remote` 装配 | ❌ client 侧无通用入口，装配清单只收官方包 |
> | **自建 HTTP 路由** | ✅ `ctx.webServer.register({ kind, path, handler(req, res) })`，`handler` 是 **Node 原生签名**，拥有完整响应生命周期 |
> | **SSE 真流式** | ✅ 浏览器实测首包 **204ms**，8 个事件按 200ms 到达 |
> | **存储域** | ✅ `ctx.storageDomain.open(spec)` 可用；`defineDomain` 在第三方 bundle 里 `ERR_MODULE_NOT_FOUND`，改为手写 spec + 自带 `zod` 依赖 |
> | 服务访问 | 直接属性必须在 `inject` 声明（否则 `cannot get property "x" without inject`）；可选访问用 `ctx.get()` |
> | 模块 import | DSH 随附包 import 不到；普通 npm 包装进 bundle 目录即可 |
> | 鉴权 | ⚠️ 路由默认无鉴权，必须自己挡（已做同源校验 + `x-dsh-todo` 头） |
>
> **P1 验收**：`list / upsert / toggle / remove` 全通；中文 UTF-8 往返正确；**插件卸载重载后数据仍在**。

### 2.2 包结构

```
dsh-plugin-todo/
├─ package.json          dsh.bundle.patch + dsh.client{platform:'web'}
├─ cordis.patch.yml      host 行 + client 行
├─ index.js              Host 入口，只做装配（open domain / 注册通道 / 注册工具）
├─ lib/
│  ├─ domain.js          todo / tag / conversation 三张表的 schema
│  ├─ dates.js           历法：离线表 + 节气 + 节日 + 短语解析
│  ├─ extract.js         调 ctx.llm.stream，结构化输出
│  └─ channel.js         对外通道（@Remote 或 HTTP 路由，按 S1 结果）
├─ client.js             **单文件** client bundle（内联历法表）
├─ data/lunar-table.json 历法表（源）
├─ locale/{en,zh}.json
├─ icon.svg
└─ docs/DETAIL.md
```

Host 侧可以多文件（Node ESM 正常 import）；**Client 侧只能一个文件** —— 这条已验证。

### 2.3 数据模型

```
todos      { id, title, dueDate, dueTime?, tag, important, urgent, done,
             notes?, rawText?, source, createdAt, updatedAt }
tags       { id, name, color }
conversation (单例) { messages[], summary, summaryUpto }
```

重要日期（生日）单独存 `{ cal:'lunar'|'solar', month, day, leap? }`，每年现算。

### 2.4 阶段与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0** | 包骨架 + 空面板 + 图标 + 装配 | 侧栏出现入口；点开是空页；禁用后彻底消失 |
| **P1** | 域 + 通道 + 列表视图读写真数据 | 建一条待办，刷新浏览器还在；删除能撤销 |
| **P2** | 抽取闭环 | 一张会议截图 → 2–3 条带日期标签的草案 → 补全 → 落库 |
| **P3** | 日历视图 | 任意年份翻月正确；2027 春节在 2/6；农历生日随年换算 |
| **P4** | 助手 | 单会话 + 滚动摘要；隔天再聊能记得上次说的事 |
| **P5** | 打包 | 干净 clone 装上即用；无密钥、无个人数据 |

### 2.5 每阶段的验证手段

- P0/P3：装进当前 profile，浏览器里截图核对（我这边可用无头 Edge 出图）
- P1：建 → 刷新 → 查；删除 → 撤销
- P2：用真实截图跑，检查草案字段与落库结果一致
- P5：`grep` 全仓扫密钥/绝对路径；`files` 白名单核对

## 三、体验标准（极致版）

不做「够用就行」。下列是**硬指标**，不是 nice-to-have。

### 3.1 AI 侧

1. **真流式**：首字 < 500ms，token 级输出。**禁止假打字机**（把整包结果做动画）。
2. **渐进式草案卡**：解析出一条就渲染一条，不等整包 JSON。第一张卡 < 1.5s 出现。
3. **粘贴即识别**：`Ctrl+V` 之后立即压缩上传并开始识别，不需要再点发送。
4. **上下文注入**：当前视图 / 筛选 / 日期范围进 prompt，问「这天有什么」不用重述日期。
5. **失败可恢复**：保留原图与输入，一键重试；超时给部分结果而不是全丢。

### 3.2 数据侧

6. **乐观 UI**：勾选 / 删除 / 新建立即生效，失败回滚并提示。
7. **全撤销**：删除、批量创建、勾完成，5 秒内都能撤。
8. **本地首屏**：打开面板先渲染缓存，后台刷新，**不闪骨架屏**。

### 3.3 操作侧

9. **全键盘**：`N` 新建、`↑↓` 移动、`Space` 勾选、`Enter` 编辑、`Delete` 删除、`Esc` 收起、`/` 聚焦对话。
10. **就地编辑**：点标题原地变输入框，不弹窗。
11. **拖拽**：日历里拖动改期；列表里拖到某个日期分组。

### 3.4 由此产生的技术硬约束

| 指标 | 对架构的要求 |
|---|---|
| 真流式 | `host.call` 的 unary 模型**不够用** → 必须有 SSE / WS / 事件通道 |
| 渐进卡片 | 增量 JSON 解析器，或让 Host 逐条推送事件 |
| 粘贴即识别 | 粘贴事件 + canvas 压缩 + 立即上传 |
| 本地首屏 | 客户端缓存（IndexedDB 或 localStorage） |

### 3.5 明确不追求（避免「极致」变成范围爆炸）

多端同步、团队协作、外部日历双向同步、Kanban 拖拽看板。

**「极致」指核心闭环的手感，不是功能数量。**

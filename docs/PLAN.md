## 关键设计决策

1. **历法放 Host 侧**（`lib/calendar.js` + `/api/todo/month`），不在客户端重复实现算法，也不把历法表塞进单文件产物。
2. **对话与抽取合并为一个端点** `/api/todo/chat`，模型用 `<todo>` / `<ask>` 结构化块表达意图，服务端流式过滤，客户端再兜底过滤一次。
3. **待办明细按需查询**（`query_todos` 工具），而不是每轮全量注入 —— 上下文不随待办数增长，且模型主动核对更不容易重复。
4. **时间锚点是动态的**：每轮请求采样当前时刻，历史消息带时间戳落库，两者配合解析「那条消息里的明天」。
5. **客户端源码拆开、产物单文件**（esbuild），因为 DSH 的 client 半只能加载一个产物。

## 已知缺口

- 法定节假日与调休不标注（需要按年维护的数据文件）
- 农历超出 1900–2100
- v1.0 之前的对话消息没有时间戳，历史显示「时间未知」
- 不支持删除单条消息，只能清空整段对话
- 助手只能新增，不能修改/删除已有条目
- 插件页展示元数据（标题/图标/详情渲染）未在 Plugins 页面实际核对过
